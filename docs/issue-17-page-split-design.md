# 소개 페이지와 포트폴리오 페이지 분리 설계 (#17)

상태: 로컬 구현 완료 · 2026-10-26
근거: [이슈 #17](https://github.com/JungYeoni/portfolio/issues/17), 현재 `src/app/page.tsx`와 `src/data/portfolio.ts`

## 목적과 경로

방문자가 `/`에서 경력과 프로젝트를 짧게 훑고, 관심이 생기면 `/portfolio`에서 작업 근거를 읽도록 나눈다. 같은 Next.js 앱과 Vercel 프로젝트를 사용한다.

| 경로 | 화면 | 내용 |
| --- | --- | --- |
| `/` | 소개 | 이름·한 줄 소개·연락처, 짧은 About, 경력, 전체 프로젝트의 기간·이름·한 줄 설명·담당 역할, 활동·수상, 자격증 이름·취득일 |
| `/portfolio` | 포트폴리오 | 현재 대표 프로젝트의 사례와 목록형 프로젝트의 기존 설명·사용 기술·외부 링크 |

`/portfolio`로 옮길 때 프로젝트 본문과 표시 순서(`sortDate` 내림차순)를 보존한다. About, 경력, 활동·수상, 자격증은 소개 페이지에만 둔다. 프로젝트 이미지 파일은 현재 저장소에 없으므로 이 작업의 전제 조건으로 삼지 않는다.

## 화면과 이동

- 공통 헤더: 화면 양쪽에 큰 `JUNGYEON`과 `portfolio`(`/portfolio`)·`about`(`/`)·테마 버튼을 둔다. 현재 페이지 링크에 물결 밑줄을 표시한다. 두 페이지에서 같은 색상 토큰과 Pretendard 폰트를 사용한다.
- 소개 페이지 목차: 본문 상단에서 `#about`, `#experience`, `#projects`, `#activity`, `#awards`, `#certification`으로 이동한다. 동아리·참여 이력은 Activities, 대회와 수상은 Awards 섹션에 분리한다.
- 소개 페이지의 프로젝트 목록은 참고 이미지처럼 한 행에 기간을 왼쪽, 프로젝트명과 `짧은 설명 · 담당 역할`을 오른쪽에 둔다. 프로젝트명은 굵게, 역할은 옅은 색으로 표시한다. 좁은 화면에서는 기간과 본문을 세로로 쌓고 텍스트를 자르지 않고 줄바꿈한다. 참고 이미지의 프로젝트명은 배치 예시이며 실제 목록은 현재 데이터의 7건을 사용한다.
- 포트폴리오 페이지: 프로젝트 섹션에 `id="projects"`를 둔다. 헤더의 `포트폴리오` 링크는 `/portfolio`로 이동한다. 프로젝트별 개별 경로와 앵커는 만들지 않는다.
- `/`의 GitHub·Email·LinkedIn·Blog·`포트폴리오 보기` 링크는 About 문구 아래에 둔다. 포트폴리오 진입 링크는 프로젝트 목록 아래와 푸터에도 둔다. `/portfolio`에는 헤더와 푸터의 `소개` 링크를 둔다. 내부 경로 이동에는 Next.js `Link`, 외부 링크에는 기존 `ExtLink`를 사용한다.
- 모바일에서 헤더의 이름·두 페이지 링크·테마 버튼이 가려지지 않는지 확인한다. 별도의 반응형 재설계와 등장 모션은 이슈 #5·#7의 범위로 둔다.

## 데이터와 문안

`src/data/portfolio.ts`를 두 화면의 단일 콘텐츠 소스로 유지한다. `Project`와 `CompactProject`에 필수 `shortDescription: string`을 추가하고, 현재 `role`이 없는 `CompactProject` 3건에 `role: string`을 추가한다. 기존 `summary`·`stories`·`paragraphs`·`stack`·`links`는 상세 화면에서 그대로 사용한다. 새 API, 데이터 복제, 프로젝트별 페이지는 필요하지 않다.

소개 목록에 들어갈 짧은 설명과 목록형 프로젝트 역할 문안 초안은 다음과 같다. 이미지의 밀도에 맞춰 프로젝트마다 무엇을 하는지 한 문장으로 적고, 구현 과정과 성과 수치는 상세 페이지에 둔다. 팀 전체 결과와 직접 맡은 일을 구분하는 현재 상세 설명을 바탕으로 썼으며, 게시 전 문안 검토 대상이다.

| 프로젝트 | 한 줄 설명 초안 | 소개 목록의 역할 |
| --- | --- | --- |
| 트립게더 | SNS 게시물에서 여행 장소를 찾아 저장하는 서비스 | 기존 `role` 사용 |
| 추크크 | 고객 행동을 분석해 추천 순위를 개선한 프로젝트 | 기존 `role` 사용 |
| 유모차 | 지역별 저출생 예산과 출생환경지표를 비교한 분석 | 기존 `role` 사용 |
| 서울숨셔 | 위치와 취향에 맞는 서울 휴식 공간 추천 서비스 | 기존 `role` 사용 |
| 솔솔 | 답변에 따라 다음 질문을 고르는 AI 면접 서비스 | 질문 선택 에이전트, API |
| 비자부기 | 비자 요건 문서를 구조화해 웹 서비스에 연결한 프로젝트 | 문서 추출·데이터 적재, 지도 연동 |
| 사회적 고립 분석 | 지역·인구집단의 고립 의심 신호를 탐색하는 분석 | 데이터 탐색, 위험 신호 검증 |

About은 기존 `profile.about`에서 핵심만 짧게 보여주고, 확인되지 않은 경력·성과 주장은 추가하지 않는다. Activities는 동아리와 대회 참가·출품 이력을, Awards는 실제 수상과 본선 진출을 표시한다. 자격증은 기존 항목의 이름과 취득일만 소개 화면에 표시하고 번호는 표시하지 않는다.

사용자 추가 요청에 따라 경력란은 기존 프로필(2026-10-05 수정)의 두 항목을 짧게 옮긴다: 트립게더(2025.09–11, 장소 정보 추출 파이프라인·연계 설계 참여), 금성출판사(2023.11–2024.09, 정보 교과 디지털 교과서 콘텐츠 검토·학습 구조 설계 지원). 트립게더의 경력 시작월은 기존 프로젝트 기간(2025.10–11)보다 한 달 이르므로 사용자 확인이 필요하다.

경력란의 기간·조직명·설명은 프로젝트 목록보다 작은 글자로 표시한다.

## 파일별 변경 계획

| 파일 | 변경 |
| --- | --- |
| `src/app/page.tsx` | 소개 페이지로 교체. 프로젝트 목록에는 짧은 필드만 표시하고 상세 본문·기술 목록은 렌더하지 않음 |
| `src/app/portfolio/page.tsx` | 현재 프로젝트 상세 UI를 옮겨 포트폴리오 경로 생성 |
| `src/app/_components/` | 공통 헤더·섹션 표시 코드를 필요한 만큼만 공통화하고, 양쪽 페이지의 링크를 연결. `ThemeToggle`·`ExtLink` 재사용 |
| `src/data/portfolio.ts` | 프로젝트 7건의 `shortDescription`, 목록형 3건의 `role`, 경력 2건 추가. 화면에서 쓰지 않는 자격증 번호 제거 |
| `src/app/layout.tsx`, 각 `page.tsx` | 공통 레이아웃·테마 스크립트 유지, 페이지별 메타데이터 설정 |
| `src/app/globals.css` | 두 경로에서 필요한 스타일만 조정 |

메타데이터 초안: `/`은 `이정연 | 소개`, 설명은 현재 `profile.tagline`; `/portfolio`는 `이정연 | 포트폴리오`, 설명은 `데이터 분석·모델링·AI 서비스 프로젝트와 직접 맡은 작업을 소개합니다.`로 설정한다. 도메인·서브도메인 설정은 이슈 #16에서 결정한다.

## 완료 기준

1. `/`에서 경력 2건과 프로젝트 7건을 확인하고, 프로젝트 상세 사례는 보이지 않는다. 데스크톱에서는 기간과 본문이 나란히 보이고, 모바일에서는 잘림 없이 줄바꿈된다. 자격증은 이름·취득일만 표시한다.
2. `/portfolio`에서 현재 7개 프로젝트의 상세 설명·기술·외부 링크를 확인한다. 기존 문단과 순서가 빠지지 않는다.
3. About 문구 아래·프로젝트 목록 아래·푸터의 포트폴리오 링크, 포트폴리오에서 소개로 돌아오는 링크, 소개 페이지 목차의 모든 섹션 앵커가 작동한다.
4. 두 경로의 제목·설명이 각각 다르고, 밝은/어두운 테마 및 모바일 헤더가 작동한다.
5. `npm run lint`, `npm run build`와 두 경로의 수동 화면 확인을 통과한다.

## 검토할 결정

1. 트립게더 경력 시작월(2025.09)과 프로젝트 기간 시작월(2025.10)이 다른 것이 맞는지.
2. 위 한 줄 설명과 목록형 3개의 역할 문안을 그대로 사용할지.
